# ADR-027：MCP 服务器的导出与导入

- 状态：Accepted
- 日期：2026-10-19
- 关联：AGENTS.md 第 8 条（导出文件不得含凭据）、ADR-023（不可信输入只产草稿）、`mcpane-storage::backup`（整机备份）

## 背景

MCP 服务器之前只能从客户端配置导入、在添加弹窗里粘贴 JSON（粘贴后直接入库，没有预览）、或从 cc-switch 迁移。导出方面，只有编辑弹窗能复制单个服务器的配置，而且内容带明文 Token。想把一批服务器分享给同事、搬到另一台机器，都没有路可走。

另有一个现存缺陷：「复制配置」写出的 `bearer` / `bearerEnv` 字段，导入解析器一律丢弃，所以复制出去再粘回来，Token 配置就没了。

## 决策

### 1. 格式：通用 `{"mcpServers": {...}}`

字段沿用「复制配置」既有写法：stdio 写 `command` / `args` / `env` / `cwd`，远程写 `url` / `headers` / `bearer` / `bearerEnv` / `env`。另外补两处：远程条目写 `type: "http"` 或 `"sse"`，这样文件直接贴进 Claude Code 也能识别；停用的条目写 `enabled: false`。

不加 MCPane 专有的外层包装和版本号。解析器本来就同时容忍包裹层与裸 map、未知字段，加一层包装只会让文件没法直接贴进客户端。导入时 slug 由名称重新推导，与手动新建同一规则。

### 2. 凭据：一律换成 `${VAR}` 占位符，不提供「包含凭据」开关

导出文件会离开本机：贴进聊天、提交到仓库、放进网盘。按 AGENTS.md 第 8 条，导出文件里不出现明文凭据。识别规则在 `server_export.rs`，按位置分层：

| 位置 | 规则 |
| --- | --- |
| `bearer` | 一律替换 |
| env / 请求头 | 名称含 token、secret、password、cookie、authorization、webhook 等词，或以 key、auth、pat、pwd、dsn 结尾（`API_KEY`、`X-Auth` 算，`AUTH_TYPE`、`KEYBOARD_LAYOUT` 不算）；`bearerEnv` 指向的 env 键无论叫什么都替换 |
| URL | 地址里内嵌的密码；查询参数按上一行的名称规则；形如密钥的路径段 |
| 命令参数 | `--api-key VALUE`、`--token=VALUE`、`KEY=VALUE`、`Header: value`（mcp-remote 的写法）；`--header=…`、`--env=…` 的取值按独立参数再认一遍 |
| 任意位置 | 值本身像凭据：Bearer/Basic 认证串、带密码的 URL、常见服务的密钥前缀（`sk-`、`ghp_`、`github_pat_`、`xoxb-`、`glpat-` 等）、JWT |

`true`、`false`、`on`、`0` 这类开关字面量不替换：`SKIP_AUTH=true` 不是秘密，替换了只会让收件人多填一项本来就知道的值。

占位符 `${VAR}` 与 Claude Code `.mcp.json` 的变量展开是同一写法：贴进 Claude Code 后，它会读同名环境变量。认证方案前缀会保留（`Bearer ${AUTHORIZATION}`）；名称看不出是凭据的 URL 只替换其中的凭据部分，保留主机等结构，收件人才知道要填什么。同一条目内的变量名不重复，原有占位符保持原样。

这套规则防的是分享导出文件时顺手把密钥带出去。它不承诺识别所有写法，所以导出框会逐条列出替换了哪几处，并明说「其余内容按原样导出，分享前请核对预览」，不让用户以为已经绝对干净。

需要连凭据一起整机迁移的，走「数据备份」：它是本机的完整还原点，权限为仅属主可读。导出与备份的定位分开，导出这里就不必再开一个凭据开关。

### 3. 导入：预览 → 勾选 → 补填 → 导入

粘贴的 JSON 或选择的文件先交给后端解析（与真正导入用同一个解析器），逐条列出：
- 前缀已被库里服务器占用的条目不可勾选，并写明被谁占用；同一批里归一到同一前缀的条目（`memory` / `Memory`）随勾选互斥，取消前一条后后一条即可选。这与 `import_defs` 只对勾选的候选去重同口径；
- 带 `${VAR}` 占位符的条目在行内给出填写框，填完一次导入就结束；
- 认不出传输方式的条目单独列出，说明已忽略。

导入时只提交勾选的条目名与填写的取值，代入是单次扫描（取值里恰好含 `${…}` 也不会被再替换一轮）。仍有占位符没填的条目**按停用入库**：带着 `${VAR}` 字面量跑起来，只会得到一条看不出原因的鉴权失败。导入结果里会说明有几个是这种情况。

解析器一并补上 `bearer` / `bearerEnv`，Codex 的 `bearer_token_env_var` 也并入通用解析；空白的 `command` / `url` 视同缺失。

### 4. 文件读写：不新增依赖

`tauri-plugin-dialog` 2.8 要求 tauri ≥ 2.12，并会连带引入 `tauri-plugin-fs`；本项目锁在 tauri 2.11.5。所以：
- **导出**：后端按勾选的 id 重新生成内容（不接收前端传来的文本，「不含凭据」的保证只在后端成立），写入「下载」文件夹。文件名为 `mcpane-servers.json`，重名时按浏览器习惯追加 ` (2)`，`create_new` 保证不覆盖已有文件。写完后用 opener 在文件管理器中定位；定位失败不影响导出，路径会显示在界面上。
- **导入**：用网页原生的 `<input type="file">`（wry 0.55 在 macOS 上实现了 `runOpenPanelWithParameters`），文件上限 1 MB。

### 入口

- 服务器页页头：「导入 ▾」（从客户端导入 / 从文件或 JSON 导入…）与「导出」，导出默认全选。
- 行尾「…」菜单：「导出…」，打开时只勾选该行。
- 添加弹窗的「导入 JSON」页签使用同一个导入面板。

### 不做

- 冲突时覆盖或改名导入（目前一律跳过并说明原因）；
- Hub 运行时展开 `${VAR}`（会改变数据面行为，需要单独评估）；
- 「从客户端导入」走同一套预览（可选后续）。

## 验证

- 后端：`(cd apps/desktop/src-tauri && cargo test -- commands::server_export commands::import::)`。覆盖：导出再导入逐字段一致、各位置的凭据都被替换且明文一个字节都不出现（已反向验证：关掉替换后用例失败）、导出登记的替换与导入要求补填的变量一一对应、重名键去重、文件不覆盖、预览冲突判定、按勾选导入并代入取值、未填全的按停用入库。
- 前端：`ServerImportPanel.test.tsx`、`ServerExportModal.test.tsx`；e2e：`e2e/servers.spec.ts`（导入预览、文件导入并补填、导出与行尾导出、两个弹窗明暗主题下的 a11y）。
- **未验证**：真机上的系统文件选择面板与「在访达中显示」。e2e 通过 mock IPC 驱动前端，碰不到系统对话框，需要在打包后的应用里手测（见 `docs/RELEASE_CHECKLIST.md`）。
